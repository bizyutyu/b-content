# DNS周りの基本を整理する

## 導入

自分でドメインを取得してWebサービスを公開しようとすると、必ずDNSの設定画面に行き当たる。Aレコード、CNAME、TXT、MX……種類は多いが、どれも「ドメイン名という人間向けの名前を、コンピュータが使う情報に変換するための対応表」という一点に集約される。

この記事では、DNSレコードの種類を目的別に一覧として整理する。

## DNSレコードとゾーンファイル

**DNSレコード**とは、ドメイン名と、それに対応する情報（IPアドレスやテキストなど）を結びつける1つの設定エントリのことだ。「`example.com`というドメインには`A`レコードとして`203.0.113.1`が対応している」のように、「ドメイン名＋種別（タイプ）＋値」の組で表される。1つのドメインに対して、複数の種類・複数件のレコードを登録できる（例: Aレコードは1つ、TXTレコードは複数、といった形）。

**ゾーンファイル**は、あるドメイン（ゾーン）に属するDNSレコードをまとめて記述したテキストファイルだ。権威DNSサーバー（そのドメインの情報を管理するサーバー）がこれを保持し、問い合わせに応じて中のレコードを返す。レジストラやDNSプロバイダの管理画面で「レコードを追加する」という操作は、実質的にこのゾーンファイルに1行追加することに相当する（画面上はGUIで隠蔽されているだけ）。ファイルには`$TTL`（レコードのキャッシュ有効期間）のような、ゾーン全体に関わる設定も含まれる。

なお、ゾーンファイルの**フォーマット**（レコードの書き方）はRFC 1035で定義されているが、**ファイル名そのものに標準の決まりはない**。BINDのような自前DNSサーバーでは、`named.conf`の中でゾーンごとに任意のファイルパスを指定する（`db.example.com`のような命名はあくまで運用上の慣習）。Cloudflareやレジストラの管理画面でレコードを編集する場合は、この実体を意識する必要はない。

## DNSレコードの種類一覧

DNSレコードは「ゾーンファイル」と呼ばれる設定の中に複数の種類（タイプ）として登録される。代表的なものを目的別にまとめると以下の通り。

| レコード種別 | 主な役割 |
|---|---|
| A | ドメイン名をIPv4アドレスに変換する |
| AAAA | ドメイン名をIPv6アドレスに変換する |
| CNAME | あるドメイン名を別のドメイン名の別名（エイリアス）として扱う |
| TXT | 任意のテキスト情報を保持する。ドメイン所有権の確認や、メール送信元認証（SPF等）、SSL証明書発行時のドメイン確認（[ACME](https://datatracker.ietf.org/doc/html/rfc8555)のDNS-01チャレンジなど）に使われる |
| MX | ドメイン宛のメールを受け取るメールサーバーを指定する |
| NS | そのドメインの権威DNSサーバー（問い合わせ先）を指定する |
| SOA | ゾーンの管理情報（プライマリサーバー、管理者メール、更新間隔など）を保持する |
| CAA | そのドメインの証明書を発行できる認証局（CA）を制限する |

Webサイトを1つ公開するだけであれば、まず触るのは**A（またはCNAME）**と**TXT**の2種類で、残りは用途が発生したときに個別に調べれば足りることが多い（例: メールを使うならMX、証明書発行元を制限したいならCAA）。

## まとめ

DNSレコードは種類が多く見えるが、それぞれが担う役割はシンプルに切り分けられる。

- A/AAAA/CNAME: ドメイン名を実際の宛先（IPアドレスや別のドメイン名）に変換する、ルーティング寄りのレコード
- TXT: 任意のテキストを公開できる汎用的な仕組みで、所有権確認や証明書発行時のドメイン確認など「証明・宣言」用途に使われる
- MX/NS/SOA/CAA: それぞれメール配送・権威サーバーの指定・ゾーン管理情報・証明書発行元の制限という、個別の目的に特化したレコード

どのレコードがどの目的のために存在するかを押さえておくと、DNS設定画面で迷いにくくなる。
